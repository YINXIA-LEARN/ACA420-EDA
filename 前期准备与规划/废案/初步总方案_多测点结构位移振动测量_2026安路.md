# 2026 安路选题二：多测点结构位移与低频振动测量终端

版本：2026-10-16 初步执行版。团队三人，约 15 个有效开发日。**报名赛题名称仍是“基于安路 PH1P35 的实时数字图像处理系统”；本页是作品工作名称和技术方案。**

## 1. 作品要解决的问题与国奖判断

桥梁、机架、实验梁等结构需要知道不同位置如何移动、振动频率是否改变。接触式传感器每点都需布线；单台相机能同时观察多个平面内测点。我们做一个可在桌面验证的**单摄像头、多测点、非接触式二维位移测量终端**，以悬臂梁为样机。它是结构监测方法的原型验证，不宣称已经能直接部署到桥梁。

国奖竞争力应来自四件同时成立的事：① PH1P35 上实时完成采集、识别、坐标/位移计算和显示，不用 PC 偷做核心；② 一个固定参考标记加多个运动测点，展示相机抖动校正与同步测量；③ 自焊照明/激励/同步副板和可交互梁工位；④ 独立量具与振动参考做可重复的误差实验、失效边界和演示。视觉位移本身是成熟研究，不能称首创。能否获国奖取决于完成质量和同场作品，不能保证。

## 2. 展示场景和可交付功能

工位：一根薄钢尺/弹性片一端夹紧成悬臂梁，梁上贴 3 个圆形高对比标记（近端、中段、自由端），底座贴 1 个**不随梁运动**的参考标记。相机固定在相对稳定的独立支架，光轴尽量垂直标记运动平面，视野内同时容纳全部标记与毫米标定尺。先做竖向 1D，横向 2D 同步输出可保留；真实可测的是相机图像平面内投影。

现场可完成：手拨梁，屏幕同步显示各点轨迹、峰值和主频；改变敲击位置/梁长度或挂载质量，展示波形/主频变化；轻碰相机支架，对照“原始位移”和“固定参考校正后位移”；用数显卡尺/百分表设置已知静态位移并读出误差；遮挡标记时明确显示“失锁/无效”，而不是继续输出假数据。显示区域同时保留实时原图、灰度/二值化切换、跟踪框、状态、安路 Logo。

**范围边界**：不做三维位移、全场应变、裂缝诊断、微米精度承诺或高频模态分析。动态最高可信频率由实际上板帧率、曝光、抗混叠和丢帧测试确定；理论 Nyquist 上限 `f_s/2` 不能直接当作工程指标，首版只针对低频振动。

## 3. 系统架构

`SC500CS → HX1P35A/PH1P35 的 MIPI 接收 → 视频时序与帧缓存 → 灰度/二值化 → 多 ROI 标记提取 → 固定参考去漂移 → 像素/mm 标定 → 轨迹 FIFO/频率计算 → OSD → HDMI`。

同一测量记录经板载 UART 输出 `frame_id,timestamp,target_id,x_px,y_px,dx_mm,dy_mm,quality,valid`，PC 只负责日志、作图、实验统计和与独立量具比对。若最终频谱在 PC 算，报告必须如实说 PC 是频谱后处理；优先把主频估计（零交叉/自相关或单频 Goertzel）做在 FPGA，完整 FFT 视资源和日程决定。

FPGA 的并行优势体现在**一帧多个 ROI 同时提取**、视频流处理与 HDMI 持续显示。官方板卡约 38k LUT、42k DFF、2160 Kbit ERAM、40 DSP，板上仅一个 FPC40 摄像头接口；芯片有 2 个 MIPI 核不等于板上有两个现成摄像头插座。视频底座从官方 `lab_ex_1/2/3` 出发，保留例程来源与修改记录。

### 可实现的测点算法

首选圆形高对比标记：每个 ROI 内先灰度/阈值，统计有效像素数 `N`、坐标和 `Σx,Σy`，中心为 `(Σx/N,Σy/N)`。固定参考同法。使用 ROI 边界、面积范围、形状/亮度稳定度生成 `quality`；低于阈值时拒测。每帧以预测坐标更新 ROI，丢失时扩大搜索或人工重置。对照算法可选边缘/模板 SAD，证明为什么首选算法更稳或更省资源。**标记质心的小数位只是数值分辨率，绝不等于实际测量精度**。

参考校正：`d_i(t) = [(p_i(t)-p_i(0))-(r(t)-r(0))] × s`，`p_i` 为运动测点像素坐标，`r` 为固定点，`s` 为经标定的 mm/pixel。若标记不共面、相机产生转动或透视变化，单个参考点只能校正共同平移；可增加第二固定参考点以估计小角度转动，但列为进阶。标定尺放在测点运动平面附近，拍摄距离、焦距与工位保持固定。应记录标定残差和重新标定条件。

### 时序与计算

为每帧在帧同步处锁存计数器时间戳，所有测点使用同一帧 ID。跨 MIPI 像素时钟、测量时钟和 HDMI 时钟用异步 FIFO/双口 RAM，不用裸多位总线跨域。至少记录输入帧、处理结果、输出帧的 ID 或时戳，显示采集到输出的帧数与估计毫秒延迟；真正光到屏端到端延迟须用 LED/高速摄影另行测量，不以内部时戳冒充。频率处理对不等间隔/丢帧要标失效；先保证时域轨迹正确，再加频域。

## 4. 工位与物件布局

俯视：相机在梁前方独立支架，梁水平置于哑光底板，夹具在左，自由端在右；底板上固定参考点 R 与尺，梁上从左到右为 P1、P2、P3。灯在两侧低角度漫射照明，避免标记反光。相机与梁不要装在同一会晃动的轻底座上。显示器放旁边，不进入相机视野。

侧视：相机镜头正对梁标记平面；激励器在梁自由端附近由低压驱动，避免其电缆拉动梁。静态校准时关闭激励，百分表/卡尺尖端在目标点同一方向测位移。相机、灯、梁、量具均可用现有实验室物品固定；无需直线导轨和复杂机加工。

副板连接：`HX1P35A GPIO → 电平/限流 → MOSFET 栅极 → 低压振动电机`；电机端加续流/抑制，电机电源与 FPGA 电源按原理图和噪声测试确定共地方式。另一路恒流或限流 LED 照明；可选 IMU 的 I²C/SPI 接 FPGA 或 PC，用于**主频交叉验证**。副板留电源、地、PWM、触发、I²C/SPI、测试点和保险/反接保护。**接线前先查开发板原理图的 GPIO 电压、电流和针脚，不把电机直接接 GPIO。**

## 6. 工程拆分与接口

### FPGA/RTL 工程

1. `camera_base`：复现官方 MIPI→DDR→HDMI，测输入 FPS/丢帧、稳定运行；保存未改基线和资源报告。
2. `gray_threshold`：流式灰度、阈值、原图/处理图切换，完成赛题基础算法。阈值可通过按键或 UART 调节。
3. `roi_tracker`：R、P1、P2、P3 四 ROI 坐标寄存器；每 ROI 的 `N, Σx, Σy` 累加、帧末除法/定点化、面积和越界判定。大范围盲搜成本高，初始 ROI 由按键/串口坐标设置；丢失后提示重设。
4. `displacement`：帧 ID 对齐、零点、参考校正、定点 mm/pixel 标定、饱和/符号处理，输出有效位。每个模块写固定输入波形仿真，尤其验证遮挡、溢出和负位移。
5. `trace_freq`：每点环形时序缓冲、波形最值/均方根、低频主频。先实现稳定轨迹与频率基线；Goertzel 或自相关依据资源与可测 FPS 选一。频域窗口长度和有效帧率在显示上标注。
6. `osd_uart`：安路 Logo、跟踪框、坐标、位移、质量/失锁、模式、FPS 和延迟；UART 数据协议版本、校验和丢包计数。
7. 集成：约束文件、时钟域审查、时序收敛、资源/DDR 带宽、长稳测试、bitstream 与源码版本对应。

### 副板/机电工程

原理图与引脚表 → 面包板/洞洞板先通 → PCB/洞洞板焊接 → 万用表查短路和电压 → 空载电机/照明测试 → 与 FPGA 低压控制联调 → 固定走线、拍摄焊接和测试证据。若定制 PCB 打样来不及，整洁洞洞板同样能证明自焊设计；报告必须附原理图和实物照片。机械工位要有夹紧、相机重复定位、可更换梁和量具测点。

### 软件/实验工程

Python `golden_model` 读取相机采样图/录制帧，输出参考点和目标点坐标，建立算法参数基线；`serial_logger` 解析帧记录、检测缺帧；`analysis` 生成位移、频率、误差与对照图。仿真向量从真实图像 ROI 导出，RTL 数值与 Python 对拍。PC 软件不参与实时位移核心计算。最终交付源码、工程、可复现实验步骤、原始数据、脚本、资源/时序报告、演示视频和答辩 PPT。

## 7. 量化验收与实验设计

**先定义指标再测，最终填真实结果。**建议的最低可演示目标是 4 点（1 固定＋3 动）持续跟踪、FPS 与有效率有日志、固定参考去漂移对照、静态至少 5 个已知位移档位每档重复 ≥5 次、动态至少 3 个激励状态主频重复 ≥3 次。画出误差条，不只给一段最好视频。

| 实验 | 参考/记录 | 结论边界 |
|---|---|---|
| 静态位移 | 百分表/数显卡尺设零与多档，往返重复；记录绝对误差、均值、最大误差、标准差、迟滞 | 写明测量范围、距离、焦距、光照；不能以像素小数位声称微米准确度。 |
| 参考去漂移 | 相机支架轻微平移，在梁不动时比较校正前后残余；另做梁运动时比较 | 单固定点只校正近似共同平移，转动/透视仍可能失效。 |
| 动态频率 | 手拨自由衰减与几档电机激励；IMU/手机传感器或已知频率驱动参考，比较主频 | 加速度可对主频，不可直接对位移幅值；失锁/漏帧样本剔除并计数。 |
| 鲁棒性 | 不同照度、部分遮挡、标记离开 ROI、相机轻碰 | 报有效帧率、恢复时间、拒测次数；不得在无效时画连续“正常”曲线。 |
| 端到端工程 | 连续运行、输入/输出帧 ID、UART 缺包、资源和时序报告 | 内部延迟与真实光到屏延迟分别表述；至少完成赛题基础项。 |

若用相机 30 fps 模式，理论 Nyquist 为 15 Hz，实际可可靠估频范围要更低且看曝光/丢帧；正式表述以实测 FPS 决定。静态误差目标不先拍脑袋定“0.01 mm”，由视场物方像素尺寸、标定残差和重复性确定。

## 9. 风险与降级顺序

1. 板卡/摄像头迟到：第一天就下单；到货前完成样图算法、仿真、工位和副板，不把时间耗在未核实的传感器参数上。
2. 相机帧率/分辨率不理想：先采稳定官方模式，再用 ROI 处理；低频范围按真实 FPS 缩小，不能臆称 720p60 可用。
3. 标记模糊/反光：缩短曝光、增强漫射光、增大标记和相机刚性；对不同视场像素尺寸重新算可测范围。
4. 跟踪资源过高：从全帧搜索降为预设小 ROI；共享除法器；频谱降为主频估计；保住视频、OSD、位移和证据。
5. 参考点校正无效：检查相机转动、深度差和底板振动；可用双固定点估计刚体运动，来不及时明确适用条件。
6. 电机干扰/梁响应不稳：手拨自由衰减作为主演示，电机为增强；动电源隔离、线缆固定。

## 10. 汇报结构与证据目录

答辩主线：实际痛点 → 桌面梁可验证缩比场景 → PH1P35 并行架构 → 自焊副板与工位 → 参考校正和多点同步 → 独立量具误差/动态对照 → 稳定性与失败边界 → 现场互动。展示算法切换、运动跟踪、处理延迟可视化，对应官方进阶方向。突出“测量仪器的可信度”，不堆没有完成的数据平台功能。

仓库建议：`rtl/`, `tb/`, `constraints/`, `pc/`, `hardware/`, `data/raw/`, `data/results/`, `docs/`, `demo/`；保存第三方例程与自研改动清单。每次发布 bitstream 标注 Git 版本、相机模式、标定系数、测试日期。提交包检查官方格式与原创声明。
