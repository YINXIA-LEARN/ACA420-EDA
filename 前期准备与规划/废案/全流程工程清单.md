# HX1P35A 多点位移作品：从零到提交的工程清单

更新：2026-10-16。状态：**仅模拟图像上的 Python 原型已运行；没有真实测量数据、没有 HX1P35A 官方工程、没有 RTL 仿真或上板结果。** 本清单是执行路线与验收标准，不是完成报告。

## 0. 板卡与赛题边界

2026 安路选题二指定 HX1P35A，主芯片 PH1P35MDG324。官方指南列约 38k LUT、42k DFF、2160 Kbit ERAM、40 DSP、片内集成 DDR、MCU、两个 MIPI 核；**板上现成专用摄像头接口为一个 FPC40**。另有 HDMI 输出、板载 AL-LINK-FT Type-C 下载器、USB 转 UART、TF 卡、千兆网、两组 40Pin 扩展、按键、拨码、LED/数码管。SC500CS 为参赛者自购的 24P、2 Lane MIPI 摄像头，指南称有 40P 转 24P 排线。硬件资源表中同时出现不同电源描述，接线须以拿到的板卡丝印与使用手册为准。

赛题基础门槛：MIPI 采集、FPGA 图像处理、HDMI 连续输出、含“安路”标识的 OSD。进阶项包括算法切换、跟踪坐标叠加、处理延迟可视化和硬件运动检测。我们的核心是实时多 ROI 追踪与位移计算，绝不能变成“PC 算法＋FPGA 只显示”。

### 板卡资源在作品中的实际用途

| 资源 | 用途 | 优先级 |
|---|---|---|
| MIPI FPC40＋SC500CS | 唯一相机输入，获取同帧四测点 | 必须 |
| 片内 DDR、ERAM | 官方视频帧缓存；ROI 状态、曲线环形缓冲 | 必须；先沿用官方视频链 |
| FPGA 逻辑与 DSP | 灰度/阈值、四 ROI 累加、坐标及位移、主频估计 | 必须；频域按资源选型 |
| HDMI | 实时原图/处理图、标记和数值/曲线 OSD | 必须 |
| AL-LINK-FT Type-C、配置 Flash | JTAG 调试、最终掉电启动 | 必须，详细流程依手册 |
| 按键/拨码、LED/数码管 | 零点、模式切换、曝光/阈值档位、状态诊断 | 推荐 |
| USB 转 UART | 逐帧测量日志、命令与异常计数 | 推荐 |
| 扩展 GPIO | 副板 LED 触发和低压激励控制 | 推荐，先核对管脚电平 |
| MCU、TF、千兆网 | 可做记录/网络扩展，但 15 天不进关键路径 | 暂不承诺 |

## 1. 当前已做与未做

- 已做：本机 `python` 为 Python 3.12；OpenCV、NumPy、Matplotlib 可导入；生成并分析 150 帧人工画面，模拟 1 固定＋3 运动标记、相机整体平移及 11 帧遮挡；输出 CSV 和曲线。单 ROI 累加 RTL 源文件及 testbench 已写。
- 未做：真实相机数据、实际像素/mm 标定、任何精度或主频实验、官方 HX1P35A 工程复现、RTL 仿真、时序收敛、焊接副板、烧录。模拟数据 0.0312 mm MAE 只检验程序对已知人工画面的响应，不是仪器精度。

## 2. 到货前可以完成的工作

1. 从安路官方/卖家获取 HX1P35A 使用手册、原理图、管脚约束、SC500CS 初始化表、`lab_ex_1/2/3` 及对应的软件版本。资料目录保留原始压缩包与版本号，不使用其他板卡的约束文件。
2. 安装该工程要求的 TangDynasty 版本及板载 AL-LINK-FT 驱动；若官方例程明确使用 FutureDynasty/MCU 工具，再安装其匹配版。离线打开工程，检查芯片型号、源文件、IP 生成、约束和综合日志。没有板卡也可尝试综合，但没有原始工程和 IP 就不宣称“环境配好”。
3. 完善本地 Python 黄金模型：从真实帧可配置 ROI、阈值和面积门限，导出期望 `N,Σx,Σy`；增加噪声、亮度、遮挡、越界和帧丢失样本。模拟数据用于开发，不用于证明作品性能。
4. 将单 ROI RTL 扩成四 ROI 并完成 testbench；验证坐标累加、帧边界、复位、遮挡、溢出。当前未检测到 HDL 仿真器，安装或使用 TD 支持的仿真流程后才能签字“仿真通过”。
5. 画工位尺寸图和副板原理图草案；GPIO 电压、针脚、电源容量、电机电流与连接器型号留 `TBD`，待板卡原理图和实物确认后再焊。

## 3. 到货当天：开箱与基线验证

1. 核对主板丝印 `HX1P35A`、芯片 `PH1P35MDG324`、摄像头 `SC500CS`，拍照存档；确认 FPC 触点方向、排线 40P/24P 和锁扣状态。**所有排线操作断电。**
2. 不接副板、不接电机。按使用手册选板卡供电方式，先看板载电源指示；万用表检查扩展排针电源/地，绝不按网上相似板子的图盲插。
3. 用板载 AL-LINK-FT Type-C 连接 PC，检查设备管理器与 TD 下载工具是否识别目标器件。先下载最小 LED/计数器工程，验证 JTAG 通道；记录配置文件、版本、耗时及截图。
4. 接官方匹配 SC500CS 与 HDMI 显示器，原封不动复现 `lab_ex_1`。观察图像、分辨率、实测帧率和稳定性。再分别复现 `lab_ex_2` 边缘处理和 `lab_ex_3` 安路 Logo OSD，保存各自运行视频与工程备份。
5. 如果基线无法稳定运行，先查电源、排线方向、相机初始化/IP 版本、时钟和约束；暂停自研模块集成。**官方视频链稳定是第一道闸门。**

## 4. 软件与 FPGA 设计顺序

### 4.1 图像链

从官方 MIPI→DDR→HDMI 工程复制一个有版本号的工作分支。搞清楚像素格式、时钟、行场同步、输入与 HDMI 帧缓冲位置，再插入灰度或二值化模块。做原图/处理图按键切换，满足基础赛题。对光照变化调阈值，优先使用稳定照明；自动曝光/阈值可做加分项但排在核心测量之后。

### 4.2 四点定位

先固定四个 ROI，R 在静止底板，P1–P3 在梁。每个 ROI 同帧累积目标像素个数 `N`、`Σx`、`Σy`，帧末计算质心；面积太小/大、触及 ROI 边缘或无像素时 `valid=0`。坐标格式和整数/小数位在接口文档中固定；防止加法器位宽溢出。ROI 位置可由按键或 UART 初设与调整；大范围自动搜索不是第一版的必要条件。

### 4.3 位移和参考点

每帧锁存同一个 `frame_id` 与时间戳。按零点键时保存四点初始坐标。对每个运动点，计算 `[本点当前−本点零点]−[参考点当前−参考点零点]`，再乘经量具标定的 mm/px 系数。R 失效时所有校正位移都失效。显示原始/校正后两条曲线，直观展示相机共同平移误差。单参考点不保证纠正相机转动、透视变化或不同深度运动。

### 4.4 轨迹、主频和输出

ERAM 环形缓冲保存一段有效位移和帧 ID；丢帧不插假点。先实现峰峰值/零交叉主频，再视实际 FPS 与资源选择自相关或 Goertzel。HDMI 画出标记框、有效状态、位移/主频、模式、实测 FPS、安路 Logo；UART 逐帧发结构化日志。内部流水线延迟和真实光到屏延迟要区分，不能只用 OSD 帧计数冒充端到端实测。

### 4.5 RTL 验证和工程门槛

每个模块单独仿真；导出真实 ROI 作为黄金向量，对比 `N,Σx,Σy`、质心、定点位移和有效位。检查像素/处理/HDMI 不同时钟域的 FIFO 或双口 RAM，不能裸跨多位总线。每次集成都跑综合/布局布线，保存资源利用率、时序裕量、DDR 带宽估算和 bit 文件哈希。上板异常先回退到前一个能正常显示的版本。

## 5. 自焊副板：细到工序

**副板目的**是稳定照明与可控低压激励，而不是增加无关元件。建议一块低压板：LED 限流/驱动、逻辑级 MOSFET 低边开关、栅极串联电阻、栅极下拉、对电机的续流/抑制、独立电机电源输入、反接/过流保护、端子与测试点。元件值须按实际电机电压、电流和 FPGA GPIO 电平选，当前不写死型号。

1. 拿到开发板原理图后制作**引脚表**：扩展口针脚号、GPIO 电压、最大驱动/输入电流、地、是否与板载功能复用。单独标识禁止连接的针脚。
2. 测电机运行/堵转电流、LED 工作电流，定 MOSFET、二极管、保护件和导线余量。先画原理图，再画洞洞板布局和走线；电源区、信号区、端子区分开。
3. 断电焊接：先电阻/二极管，再 MOSFET、端子、排针，最后 LED/外接线；每焊几件检查焊点、桥连、极性。电机和电源线做应力固定，不让焊盘承受拉力。
4. **未接 FPGA 前**用万用表做电源正负短路、地连续性、栅极下拉、二极管方向检查；外部限流电源从低电流限制起调，先测 LED、再测电机开关。记录空载/运行电流和板上电压。
5. 单独给 FPGA 跑慢速 GPIO 翻转工程，先示波器/万用表看输出，再连接副板信号。需要共地时按原理图连接单一明确参考地；电机电源不要从 GPIO 取，噪声/反灌出现就停机排查。
6. 与视频链同开时观察花屏、失锁和 UART 错误；电机启停不能导致摄像头复位。外壳/支架固定，线缆不拉梁也不碰相机。
7. 保存原理图、BOM、焊接前后照片、电测表及故障记录。IMU 是可选的主频交叉验证模块，不应抢占上述核心时间。

## 6. 下载、运行、掉电启动：操作顺序

**下面是检查顺序，不是凭空编造某一版 TD 的菜单名称。实际按钮、文件扩展名、Flash 地址与模式以 HX1P35A 使用手册及官方样例为准。**

1. TD 打开与该芯片匹配的官方工程，确认顶层、器件型号、管脚约束及 IP 都无缺失；先仿真关键自研 RTL，再综合、布局布线、静态时序检查，生成配置文件。
2. 板卡断电连接相机/HDMI，按手册上电并通过板载 AL-LINK-FT Type-C 连电脑。用下载工具识别 JTAG 器件链与芯片 ID。识别不到先解决驱动/电源/下载器，不跳过。
3. **先做易回退的 JTAG 在线下载**：下载官方 LED 基线，再官方视频工程，最后自研版本。每次保留上一个能跑的配置文件。在线配置通常掉电不保留，具体以板卡手册确认。
4. 自研版本逐步启用：摄像头/HDMI → 灰度/二值化 → ROI → 位移 → OSD/UART → 激励。每步现场看图像、帧计数、异常标志和日志，记录失败点。
5. 最终版本稳定后，才按官方手册把对应配置镜像烧入**该板实际启动所用**的非易失存储，并执行工具校验；重启/断电再上电，核对版本号和完整演示。指南列 Flash 资源，但**不能只凭容量猜启动芯片、烧写地址或选错镜像**。
6. 最终提交包保留源工程、约束、IP 版本、可复现生成说明、配置文件校验值和短视频。不要只交一个无法追溯源码的 bitstream。

## 7. 真实数据与国奖级证据

1. **标定**：固定视场，在标记运动平面放已知间距尺，算 mm/px；多次重装相机再测标定变化。记录镜头距离、分辨率、曝光、光照和标记大小。
2. **静态准确度**：用百分表/数显卡尺独立施加至少 5 档已知位移，每档往返和重复 ≥5 次；报告均值误差、最大误差、标准差、迟滞和拒测率。数值不能从模拟画面搬用。
3. **动态**：手拨梁做自由衰减，改变梁长度/附加质量；若电机可控再做多档激励。可用 IMU/参考传感器比主频，但不能把加速度直接当位移真值。实际可测频段由相机真实 FPS、曝光、漏帧和频谱实验决定。
4. **参考点价值**：梁不动时轻微平移相机，比较校正前后残余；转动相机时展示方法边界。不能只选最成功的一段视频。
5. **鲁棒性**：遮挡、光照变化、标记出 ROI、连续运行；有效/失效状态、恢复时间、丢帧和 UART 错包均记录。报告低亮度下能否工作，不编造自动曝光功能。
6. **工程指标**：实际输入帧率、输出刷新率、目标跟踪有效率、FPGA 资源、时序裕量、连续运行时长、内部处理延迟。测真实光到屏延迟需另设外部参考。

## 8. 三人分工与先后依赖

可自行分人，但至少保证 A：官方视频链与综合/烧录；B：RTL 测点及定点/OSD/UART；C：工位、副板、Python 黄金模型与真实实验。A/B 每天同步像素格式、时钟和接口；B/C 每天同步 ROI 数据格式、阈值、标定与有效位；三人共同做端到端联调和报告。三人都应会最小回退下载，避免一个人不在就无法演示。

**关键路径**：官方资料＋板卡到手 → 复现视频例程 → 自研算法接入 → 真实标定 → 重复实验 → 稳定演示 → 提交。副板能并行，但不能取代视频链。按 15 个有效日规划，D6 必须看到稳定视频，D9 必须看到真实多点位移，D12 必须形成第一版误差表，D15 冻结功能与提交材料。若到货延迟，应从扩展项和美化减工作量，不能把实验真实性删掉。
